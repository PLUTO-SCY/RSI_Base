# 实验协议、研究入口与四卡预算

本文件是拟采用的协议。数量和阈值为起始设计值，未经本机实验校准；变更要产生新的实验配置。

## 1. 数据角色与可见性

首先从训练来源中确定任务级/实体级 group，再划分，最后采集轨迹；不把同一题的不同 rollout 分到不同集合。

| 集合 | 用途 | Meta/Task 可见性 |
| --- | --- | --- |
| D_weight | 任务执行、诊断、训练数据采集 | 输入可见；训练 verifier 可用其标签 |
| D_search | harness 搜索、失败分析、排名 | 可见搜索侧反馈；永远不转成 SFT 数据 |
| D_select | shortlist 确认和阶段晋升 | 默认仅返回固定聚合指标与决策，不回传答案/逐题轨迹 |
| D_calibration（需要时） | proxy evaluator 校准/训练 | 独立训练侧数据；不得混入最终测试 |
| D_test | 固定模型/harness 之后的最终评估 | 只给 Task 输入，不给答案；结果不回流本次选择 |
| D_ood | 跨任务、模型、环境或分布验证 | 与最终测试同样隔离 |

数学去重至少按来源 ID 和标准化题面；有题族或可获得的变体关系时做 group 划分。检索任务需记录语料和索引，工具任务需记录 schema，交互环境需记录 reset seed 和环境版本。

D_select 被多轮查询仍会产生自适应过拟合。轮数、查询次数、候选上限预先固定并记账；可用分层 rotating folds 做稳健性检查，但不能因此宣称严格独立。正式结论仍依靠最后冻结后的 D_test/D_ood。

发布最终测试结果后若据此继续开发，下次研究使用新的冻结版本/时间窗口或明确将旧测试降级为开发集。

## 2. 建议的首版默认

- 模型候选：Qwen3-4B；显存/支持不足则用同系列更小 dense 模型，并另存实验定义。[官方 model card](https://huggingface.co/Qwen/Qwen3-4B)
- 算法：固定外部 Meta → EditHarness → 新接口下成功轨迹采集 → LoRA SFT → 验证完整快照。
- 先做一个 seed、一个任务、一个真实小循环；随后扩展两任务、3 轮、每轮 2 个候选。
- pilot 每轮最多采集 512 个训练任务，每任务最多 2 次 rollout；仅对一个 shortlist 候选训练。
- rollout 先以总输出 2048 tokens/episode、每次调用 512 tokens、最多 8 次调用为起点；三者均由宿主执行。
- LoRA 初始 rank 16、1 个短训练阶段、micro-batch 1；学习率先小范围校准后冻结，记录实际训练 token，而不只记 epoch。
- 数据默认只使用当前 harness 的验证成功轨迹；历史回放比例作为独立干预，兼容性不满足时禁止混用。
- 若成功样本不足预设门槛（设计值 64），记录 NO_UPDATE。可以单独报告 harness-only 分支，不能静默混入测试数据或教师答案。
- 首个研究规模候选：D_weight 2048、D_search 128、D_select 128，均从合法训练池分出；每轮 search 可用其中 64 个任务。实际数量经去重与环境 group 划分后确认。
- pilot 上限用于工程验证；正式评测按官方完整划分或明确标注子集报告。不能拿 pilot 子集分数比较官方榜单。

这些默认不是最优参数。它们的目标是以可控成本发现接口、数据质量和阶段交接问题。

## 3. 必要对照

| 对照 | 冻结/改变的内容 | 回答的问题 |
| --- | --- | --- |
| Static | 固定 W0、H0，不执行学习 | 初始能力与重复测量噪声 |
| Weight-only | H0 固定；同样的训练机制 | 权重更新单独的贡献 |
| Harness-only | W0 固定；同样的提案机制 | harness 搜索单独的贡献 |
| Sequential W→H | 先用完权重阶段预算，再搜索 | 收益是否只是执行过两种优化 |
| Alternating H→W | 多次小步交替 | 共演化闭环相对于单侧和单阶段的价值 |

研究规模从 Static、H-only、W-only、Alternating 开始；Sequential 在比较切换/效率时必须加入。方法比较既报告组件预算，也报告实际总资源；Static 作为能力锚点，本身不消耗同等改进预算。

对照使用同一 seed harness、初始模型、训练来源、任务划分、单次推理上限和最终评估协议。模型冷启动若确有必要，必须在所有相关条件中共享；不能让某个方法独占更好的 teacher 数据。

两种预算比较分别回答不同问题：

1. **组件预算匹配**：H 候选数、W 训练/rollout 上限匹配，用于分析机制。
2. **总资源匹配**：端到端 GPU 时、API 用量和墙钟上限匹配，用于分析效率。

单侧方法可在总资源内重新分配预算。若只做了前者，不声称后者也得到证明。

## 4. 归因与泛化

### 2×2 交叉配对

在相同的评估协议和每题调用预算下比较：

| | H0 | Ht |
| --- | --- | --- |
| W0 | Y00：原始基线 | Y01：harness 的即时收益 |
| Wt | Y10：权重在旧接口下的迁移 | Y11：完整组合 |

可报告交互项 Y11−Y10−Y01+Y00 与区间。它描述所选统计尺度上的交互，不自动证明底层机制协同。接口不兼容的配对须报告兼容失败率，不能忽略后只报成功子集。

### 泛化轴

- 同任务新实例：正常 held-out。
- 新任务族/模板/工具组合：模板或 group OOD。
- 相同 Ht 换模型：先验证接口兼容，再测跨模型迁移。
- 相同 Wt 换 harness：检查是否只学会特定接口。
- 新 benchmark/环境：采用对应官方评分；不在看过结果后再调 transfer harness。
- 多轮遗忘：对固定通用能力集合重测，给出初始/最终变化。

迁移矩阵中的每个单元格都保留自己的 benchmark metric。没有合理归一化定义时不平均异质指标。

## 5. 评估器、晋升与统计

EvaluationRecord 至少包含逐题 score、完成状态、错误类别、快照/协议/数据/评分器 digest、种子和用量。

- 小规模筛选按 D_search 排名；只在 D_select 上确认少量候选。父代与子代使用相同题目和 attempt 数。
- MVP 的晋升先使用预先固定的最小增益、非回归约束和成本上限；低证据下输出 INCONCLUSIVE 并保留父代。
- 主报告使用至少 3 个独立演化 seed；预算受限的单 seed 结果标为 pilot。
- 对逐题配对差值做 bootstrap 区间；存在任务族/仓库关联时以 group 为重采样单位。演化 seed 的差异另报，不能用大量 rollout 掩盖 seed 数过少。
- 同时测试许多候选并反复查看 dev 时，普通 95% 区间不提供完整的序贯错误控制。若课题需要严格错误率，单独采用预注册的多重/序贯检验方法。
- pass@1、mean@k（k 次平均成功率）和 pass@k（k 次至少一次成功）分别定义，不能混写。
- 最终指标默认以 benchmark 官方 scorer 为准，项目自定义指标另报。

错误处理预先固定：模型格式错、非法动作、超出模型/工具预算和自身无法完成计任务失败；服务故障、环境创建失败、驱动问题等计基础设施错误，采用有上限的同条件重试。必须报告 assigned/completed/infra-error 覆盖率；不得通过丢弃困难或失败样本提高均值。

一次基础设施错误是否使整次报告无效，取决于预先固定的覆盖门槛和官方协议。主报告同时列出重试成本及未完成任务，不能只报告成功执行部分。

## 6. 三条可直接在框架上开展的研究线

### A｜Evaluator：便宜评分是否选对真正有用的改进？

最近邻：HarnessForge 的候选筛选、CoEvo-RSI 的验证晋升、CoHARL 的 evaluator integrity。

复用标准候选、快照、轨迹和最终 scorer；只替换 SearchEvaluator，比较规则、proxy judge、级联/校准评分。贡献候选是同一候选池下的选择质量与反馈成本，不宣称“首次使用 evaluator”。

最小实验：先固定 10–20 个候选和原始轨迹，用不同 evaluator 离线重评分；以独立 gold 评估为参照，测 pairwise ranking、误晋升率、最终 regret 和调用成本。再做小规模在线循环检查 evaluator 改变数据分布后的效果。

推翻条件：省下的评分成本被错误晋升和重训抵消，或 gold 表现无改善。需单列误判不确定性、长轨迹成本和 judge 版本。

### B｜效率：将下一份预算投给 H、W 还是数据？

最近邻：WHALE 的 adaptive phase 切换、CoHARL 的 pool 调度、PBT 的动态训练安排。

复用三种改进算子和统一账本；以预算分配器替代固定 phase 长度。增量候选是跨算子成本可比的决策，而非仅重命名 patience。

最小实验：固定两个任务和总资源，比较固定交替、patience、基于近期收益/不确定性的选择器。报告 anytime 曲线、达到预设质量所需的总成本、失败/重载/Meta 成本和最终得分。

推翻条件：优势只出现在未记账的额外评估后，或在第二个任务失效。先校准真实 throughput，再估计实验总耗时。

### C｜泛化：权重与 harness 是否形成过窄的互相适应？

最近邻：ADAS 的迁移问题、HarnessForge 的配对适应、CoEvo-RSI 的接口失配、CoHARL 的共享策略种群。

复用 2×2 配对、历史 archive 和数据配比；比较单 harness 训练、兼容历史回放与小规模多 harness 训练。贡献候选是可归因的迁移/遗忘权衡，而非单纯增加 benchmark 数量。

最小实验：一个来源任务形成 Wt/Ht，冻结后在新模板、另一模型和第二个环境评估；匹配训练 token 和推理预算。测任务成功、接口失败、通用能力退化与成本。

推翻条件：收益只在训练 harness 生效，跨模型/任务不改善或遗忘明显增加。需要将接口不能执行与模型能力不足分开诊断。

这些都是待验证问题；框架首版不预设某个研究组件一定有效。

## 7. 四卡资源安排

先在实际运行上下文记录 GPU 型号/显存、拓扑、驱动、CUDA、CPU/内存、存储和缓存位置；本轮 nvidia-smi 无法读取驱动，不给宿主硬件型号下结论。

| 条件 | 起始方案 | 扩大前验证 |
| --- | --- | --- |
| 4×约 24GB | 更小模型或 4B LoRA、短上下文、micro-batch 1 | 实测峰值显存；不承诺 4B 的任意长上下文可用 |
| 4×约 48GB | 4B LoRA，逐步增加上下文和并发 | 推理 KV 与训练 activation 分别测量 |
| 4×约 80GB 或更多 | 4B 基线后可尝试 7B/8B 与 GRPO | 多轮 rollout、模型重载、组有效率 |
| 驱动/容器不可见 GPU | 先完成 CPU 契约与恢复 | 不把模拟成功当 GPU 成功 |

约 4B 个 bf16 参数仅权重就约 8GB（十进制）；还需 activation、adapter/梯度/优化器、KV cache 和框架开销。内存与吞吐不能从参数量或 GPU 数单独推断。QLoRA 是后续明确标注的替代 recipe，先验证量化训练与 serving 的一致性，不默认与 bf16 等价。

生成阶段根据显存使用副本或并行；训练阶段暂停推理并独占所需 GPU。Meta 使用外部端点或本地服务都可，先记录其真实成本，不预订付费资源。

## 8. 预算公式与校准

以 episode 计的上界示例（单任务、单 seed）：

~~~text
R = 3 轮
K = 2 个 harness 候选
search = 每候选 64 题 × 1 attempt
select = 父子各 128 题 × 1 attempt
weight = 512 题 × 最多 2 attempts
diagnose = 64 episodes
handoff/smoke = 最多 8 episodes

N_round <= 2*64 + 2*128 + 512*2 + 64 + 8 = 1480
N_before_final <= 64 baseline + 3*1480 = 4504 episodes
~~~

这是最坏调用数量的设计示例，**尚未加最终测试、交叉配对和 Meta 模型调用**。真实日志中复用允许复用的诊断/父代评估可减少调用，但必须记录缓存命中及其协议键。

若每 episode 输出上限 2048 tokens，上述上界仅输出已约 922 万 tokens；多轮 prompt 重复处理还会产生大量输入 token。因此不能把“只训 4B”理解为整套实验便宜。

~~~text
GPU-hours = 各阶段实际占用 GPU 数 × 该阶段运行小时，逐阶段求和
wall-clock = 生成 + 工具/环境 + 训练 + Meta + 重载 + 评测 + 调度等待
API-cost = 每类服务实际输入/输出用量 × 当次记录的单价
~~~

不把训练和推理的 token 吞吐混成一个数。prefill、decode、环境等待、成功轨迹比例和 SFT token/s 分开校准。固定美元总额与具体吞吐在运行前配置；预算约束是多维上限，不强行将 GPU 时与 API 美元相加。

先为冻结最终评估预留预算，再分配搜索和训练。并发调用预留一起计入上限；若预算不足以完成声明的最终测试，先缩小整套实验定义或停止，不能消耗全部优化预算后省略不利的评测部分。

P1 的资源 spike 用 32–64 个真实 episodes、一个小 SFT batch 和一次重载测量每个分量，再外推 pilot，并留出失败/重试余量。除非拿到实测值，不给“完整实验需要多少小时”的伪精确承诺。

## 9. 结果与复现包

每次研究报告携带：

- 源码 commit、resolved config、依赖锁/镜像与硬件清单；
- 数据来源、revision、样本 ID、去重/划分结果及 verifier 版本；
- 初始/最终快照与完整谱系、所有候选状态和手工干预；
- 逐题指标、覆盖率、错误/重试、多个 seed 与不确定性；
- 端到端实际预算、anytime 曲线和冻结的最终选择；
- 运行命令与 artifact manifest；重放所需资产的可访问位置。

无法逐 token 复现外部服务时，至少重建输入、配置、选择路径和评分；保留服务返回的 model/version 信息，并把非确定性限制写清楚。
